# خطة التنفيذ

## 1 — الأساس (منفذ أوليًا)
إنشاء خدمة Node.js مستقلة، حفظ أسرار مشفر، عزل الأنظمة بالتوكن، جلسات متعددة، QR، إرسال نص، أحداث موثقة، تشغيل Docker، اختبارات منطقية.

## 2 — اختبار التكامل الفعلي (معلق على رقم تجريبي وبيئة VPS)
اختبار إصدار Baileys المثبت مع QR وإرسال واستقبال رقم فعلي. فحص استعادة المفاتيح بعد restart. اختبار انقطاع الشبكة وإلغاء الربط. اختبار توقيع webhook وإعادة تسليمه عند انقطاع البوابة. قياس CPU/RAM لكل حساب قبل وضع حدود تشغيل.

## 3 — استكمال النقل
إرسال واستقبال الصور والصوت والفيديو والمستندات مع حدود حجم ومدة، streaming، وتأمين جلب الملفات ضد SSRF. تحديد مسؤولية نقل الملف قبل انتهاء رابط المزود. تصميم نموذج أحداث موحد بالإصدار v1 مع وقت الرسالة الأصلي ومعرفها ونوع المحتوى وعلامة history/live.

## 4 — الاعتماد الإنتاجي
OpenAPI، اختبارات HTTP وصلاحيات شاملة، حد معدل الطلبات ومحاولات المصادقة، مراقبة السعة وdead-letter وسياسة احتفاظ، نسخ احتياطي واستعادة وتدوير مفتاح التشفير، مراجعة اعتماديات وlockfile، وتثبيت digest صورة Docker. لا نشر تلقائي عند حفظ main؛ release معتمد للإنتاج.

## شروط القبول
لا تكرار غير مقصود بعد retry؛ الحالات غير المؤكدة لا يعاد إرسالها عميانيًا. لا كشف أسرار في السجلات. عزل حسابات الأنظمة. عدم فقد الأحداث المسجلة عند restart. استعادة جلسة سليمة دون QR جديد. توثيق حدود الموارد بقياس حقيقي.

## قرارات مطلوبة للنشر فقط
اسم المستودع النهائي، عنوان VPS وطريقة الوصول، نطاق الخدمة وTLS أو VPN، عنوان webhook الخاص بالنظام المستهلك، ورقم الاختبار. لا ترسل أسرارًا في المحادثة؛ تضبط مباشرة في إعدادات السيرفر.
