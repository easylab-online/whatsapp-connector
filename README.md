# EasyLab WhatsApp Connector — 0.1.0

موصل مستقل بين الأنظمة وحسابات واتساب. Node.js 24 + Baileys على VPS، دون واجهة أو CRM أو أرشيف محادثات. هذه نسخة أولية قابلة للاختبار وليست نشرًا إنتاجيًا معتمدًا.

## المنجز
- API بتوكن Bearer مختلف لكل نظام، مع عزل ملكية الجلسات.
- عدة جلسات، عرض QR الخام، تشغيل وإيقاف وإلغاء ربط.
- حفظ مصادقة Baileys ومفاتيح Signal في SQLite مشفرة بـ AES-256-GCM.
- استعادة الجلسات النشطة، ومنع الاتصال المتكرر، وتأخير تصاعدي مع jitter.
- إرسال نصوص فردية مع Idempotency-Key وحفظ نتيجة التنفيذ؛ النتيجة المجهولة لا يعاد إرسالها تلقائيًا.
- استقبال أحداث الرسائل وتحديثاتها في طابور مشفر، مع HMAC وإعادة محاولة حتى نجاح Webhook.
- UUIDv7، health.json، Docker Compose، اختبارات محلية.

## التشغيل
1. `cp .env.example .env`
2. توليد MASTER_KEY عشوائي 32 بايت بصيغة base64، وتوكنات طويلة مستقلة وWEBHOOK_SECRET.
3. ضبط CLIENTS_JSON: ownerId هو هوية النظام المستهلك؛ ليست قيمة يرسلها العميل مع الطلب.
4. ضبط WEBHOOK_URL ثابت موثوق HTTPS. لا يسمح للعميل بتحديد عنوان callback.
5. `npm ci` ثم `npm start`، أو `docker compose up -d --build`.
6. الخدمة ترتبط محليًا افتراضيًا. استخدم reverse proxy مع TLS وحدود معدل الطلبات، أو شبكة VPN موثوقة. لا تعرض المنفذ مباشرة للعامة.

## API
كل المسارات عدا GET /health.json تتطلب Authorization: Bearer TOKEN.

| Method | Path | Purpose |
|---|---|---|
| GET | /health.json | الإصدار وتاريخ النسخة وحيوية العملية؛ لا يعني اتصال الأرقام |
| POST | /v1/sessions | إنشاء جلسة وبدء الاتصال |
| GET | /v1/sessions | جلسات النظام صاحب التوكن |
| GET | /v1/sessions/:id | حالة جلسة |
| GET | /v1/sessions/:id/qr | QR خام مؤقت وسري، يحول لصورة في النظام المستهلك |
| POST | /v1/sessions/:id/start | تشغيل أو استعادة |
| POST | /v1/sessions/:id/stop | إيقاف محلي دون إلغاء ربط واتساب |
| POST | /v1/sessions/:id/logout | إلغاء الربط؛ يتطلب socket قائمًا |
| POST | /v1/sessions/:id/messages | إرسال نص فردي |

جسم الإرسال: `{"to":"968XXXXXXXX@s.whatsapp.net","text":"مرحبا"}` مع `Idempotency-Key` فريد. إعادة نفس المفتاح بجسم مختلف ترجع 409. submitted تعني قبول المكتبة، ولا تعني التسليم للطرف الآخر. pending بعد انهيار العملية وunknown بعد خطأ إرسال يحتاجان مصالحة؛ لا تستبدل المفتاح عشوائيًا.

## أحداث Webhook
الغلاف: id, type, sessionId, ownerId, receivedAt, data. الأنواع: connection.open, connection.closed, message.upsert, message.update. حمولة الرسالة قريبة من Baileys وتحتاج طبقة تطبيع في البوابة؛ ليست عقد محتوى عابرًا للمنصات بعد.

التوقيع: HMAC-SHA256(secret, timestamp + '.' + raw_body)، في X-Signature. الوقت بالميلي ثانية في X-Timestamp ومعرف الحدث في X-Event-Id. على المستقبل مقارنة التوقيع بأمان، رفض الأحداث القديمة (مثلًا أكثر من 5 دقائق)، منع تكرار id، وتأكيد 2xx فقط بعد الحفظ الدائم. عند نجاح التسليم يحذف محتوى الحدث محليًا. البيانات هنا طابور نقل مؤقت وليست أرشيفًا.

النقل at-least-once؛ التكرار ممكن عند انقطاع الاتصال بعد حفظ المستقبل. ولا يمكن ضمان exactly-once لدى واتساب. الوسائط لا تُنزّل تلقائيًا حاليًا؛ وصول metadata لا يعني حفظ الملف.

## إدارة الأسرار
ملف .env خارج git بصلاحية 600. قاعدة البيانات مشفرة الحقول؛ ملف SQLite نفسه ليس تشفير قرص كامل. احتفظ بنسخة محمية من MASTER_KEY منفصلة عن القاعدة؛ تغيير المفتاح بلا ترحيل يفقد القدرة على فك البيانات. CLIENTS_JSON وWEBHOOK_SECRET تحفظ في إعدادات السيرفر المحمية. لا تطبع QR أو محتوى الرسائل أو مفاتيح الجلسة في السجلات.

## التشغيل والتوسع
نسخة تطبيق واحدة مع volume دائم؛ لا تشغل نسختين على نفس الحساب أو قاعدة SQLite. قناة Webhook واحدة للبوابة الموثوقة تحمل ownerId لعزل الأنظمة؛ تعدد وجهات callbacks ليس منفذًا. راقب حجم طابور الأحداث ومساحة القرص؛ لا توجد آلية ضغط خلفي أو تنبيهات سعة بعد. سجل مفاتيح الإرسال يحتفظ بالنتائج المصغرة لمنع التكرار ويحتاج سياسة احتفاظ معتمدة لاحقًا.

## التحقق
`npm test` و`npm run check`. اجتازت النسخة 5 اختبارات، تشمل تشغيل HTTP والمصادقة والإغلاق السليم. الاختبارات الحالية تغطي تشفير الأسرار والأحداث، عزل المالك، منع الإرسال المكرر وتعارض المفتاح، منع الاتصالات المتزامنة، وحالة الإرسال المجهولة. لا تثبت هذه الاختبارات نجاح ربط رقم فعلي.

## الحدود والمرحلة التالية
- لم ينفذ رفع/تنزيل الوسائط، توثيق OpenAPI الكامل، rate limiting داخل التطبيق، تدوير المفاتيح، مراقبة السعة، أو CI للنشر.
- يلزم اختبار رقم حقيقي: QR، إعادة تشغيل الحاوية والسيرفر، فصل الشبكة، الخروج من الأجهزة المرتبطة، وتعافي Webhook.
- Node.js node:sqlite قد يصدر تحذير API تجريبية حسب إصدار Node المحدد.
- Baileys غير رسمية ولا تضمن تجنب تقييد الحساب. استخدم رقم اختبار أولًا.
- طبق من toEasy-5 ما يخص خدمة API فقط؛ لا ضرورة لإنشاء app/panel/landing لخدمة بلا واجهات.
